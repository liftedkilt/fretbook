# Fretbook

Self-hosted tabs, chord sheets, and sheet music for bass and guitar.

- **Tabs and bulk import**: import from Songsterr, Ultimate Guitar links, Guitar Pro (3–8), MusicXML (partwise, timewise, and compressed `.mxl`), MIDI, plain ASCII tab (`e|---3---|`), ChordPro, or start blank. Drop multiple files, folders, or a `.zip` archive at once with per-file progress and duplicate detection (skip, replace, keep both). Standard notation and tab rendered by [alphaTab](https://alphatab.net).
- **Play along**: with an audio file (uploaded, downloaded from the YouTube video Songsterr syncs to, or downloaded from any YouTube link you paste on the song page), the score follows the recording. Tap `T` on each bar to line it up, or press Auto-sync to have the bar marks estimated from the audio and fix only the ones that are off. Without audio, alphaTab's synth plays the tab.
- **Note highway**: switch between **Tab**, **Highway** and **Split** view on any tab song page (remembered per user). Notes travel along coloured string lanes toward a hit line with fret numbers, sustain tails, technique glyphs (hammer-on/pull-off, slides, bends, palm mute, vibrato, harmonics), chord blocks with chord names, bar and beat lines, and upcoming section labels.
- **Fretboard**: in the player's Sync & audio panel, switch on **Show the fretboard under the score**. An SVG neck for the track's own strings, tuning and capo lights the notes sounding now and fades the next three. Label the dots with note names, intervals (from a root you pick) or fret numbers, and mirror it for left-handed players. It follows the synth and a recording alike.
- **Wait mode**: on a tab without a recording, open the player's Sync & audio panel and press **Wait for me**. The cursor stops on each note of the chosen track until the microphone hears you play it (the right note in any octave counts by default). The other tracks play as backing, or turn the synth off. It needs microphone access, which browsers only give on HTTPS pages or `localhost`, so serve Fretbook over HTTPS (behind a reverse proxy with a certificate). A beat of several different notes is checked as a chord, by the pitch content of the sound rather than string by string, so it is lenient (a missing or slightly wrong string still counts) and you can skip a beat; turn that off in the panel to accept any one note of the chord. On a chord sheet, press **Wait for me** above the sheet: the chord that is lit is the one to strum, and the next lights up when it is heard.
- **Scored play-along**: in the same panel press **Score my playing**, then play along with the recording or the synth without stopping. Each note of the chosen track is graded on time, early, late, wrong or missed, with a live accuracy and streak, and the highway and the notation colour each note by its grade. At the end of the song (or the loop) a results screen shows the score, stars, accuracy per section and a heatmap of bars, and **Practise this section** loops the weakest part. The practice log records the time as a scored session with its accuracy, and the personal best per song, loop and speed is kept in this browser. Wear headphones so the microphone does not hear the recording, and run the latency calibration in Settings first. Same HTTPS requirement as wait mode.
- **Chord sheets**: lyrics with chords over them, stored as ChordPro. Paste an Ultimate Guitar style "chords over lyrics" sheet, or an Ultimate Guitar chords link, and it is converted. Transpose and print.
- **Chord diagrams and a chord library**: a chord sheet shows a diagram for every chord it uses, for guitar, bass or ukulele and the common alternate tunings. Diagrams follow transpose and flats, a `{capo:}` is noted and sounds in the strum, and each chord has a voicing picker (the choice is remembered per song in this browser). Shapes are generated by Fretbook, not copied from a chord table. A ChordPro `{define: Am7 base-fret 1 frets x 0 2 0 1 0}` is offered first, and the PDF export prints the diagrams you picked. **Tools → Chord library** searches any chord name, lists its voicings and strums them.
- **First run and demo songs**: an empty library opens on a welcome (import, demo songs, instrument, tuner, beginner course); three bundled original songs add with one click and remove again. `FRETBOOK_DEMO_MODE` runs a read-only public demo that resets nightly. See the [demo guide](docs/guides/demo.md).
- **Exercise generator**: **Tools → Exercises** writes scales and modes (in a fret position or CAGED shape), arpeggios, finger drills, chord-change and strumming drills, and bass root-fifth-octave or walking lines for any instrument and tuning, previews the tab and saves it to the library as an ordinary song, so every player mode works on it. See the [exercises guide](docs/guides/exercises.md).
- **Export**: MusicXML (opens in MuseScore, Guitar Pro, and other tab apps), MIDI (for DAWs), ChordPro, Fretbook JSON, and PDF. The PDF is engraved in the browser by alphaTab, then paged so a staff is never split, with the title, artist, tuning, and track name on every page. Chord sheets export to PDF too.
- **Lessons and courses**: step-by-step courses for guitar and bass (**Lessons** in the sidebar, **Tools → Lessons** on a phone). Lessons are Markdown files with chord diagrams, fretboards, tab excerpts, generated exercises, songs from your library and video or audio clips; each lesson opens the next, a pass condition (a score at a tempo, or wait mode) is reported by the player when you play the whole song from the lesson (or by hand), or checked against your practice log, where only a wait-mode run played all the way through counts, and **Continue** returns to where you left off. Progress is per user and part of the library backup. Administrators write lessons in the app (Markdown with a live preview) or drop lesson packs (zips) into `FRETBOOK_LESSONS_DIR`. See [Writing lessons](docs/lessons.md).
- **Setlists**: named, ordered lists of songs for a rehearsal or a gig. Reorder by dragging or with the keyboard, add a note per song (key, capo, "skip solo") and a transpose per chord sheet, then _Play through_ to step from song to song (Alt with ← or →). _Export PDF_ makes one file with a contents page followed by every song. A song can be in many setlists, and setlists are part of the library backup.
- **Ear and fretboard trainer** (_Tools_): find the named note on a string by tapping the fretboard or playing it, against the clock with per-string accuracy and speed; name intervals and chord qualities by ear (buttons, or play the interval or chord back: a strummed chord must match the question's root and quality). Games count toward the practice log's minutes and streak. Microphone answers need HTTPS or `localhost`, like the tuner.
- **Difficulty and recommendations**: every song gets a 1–10 difficulty: a tab from its score (note density at tempo, position shifts, stretches, techniques, chord changes, rhythm), a chord sheet from its chords (how many different ones, how many are barre or extended chords, how often the chord changes per line), shown on the library card with an explanation on the song page, and the library sorts and filters by it. The _Practice_ page suggests songs a little above your recent scored level, loops that scored poorly, and songs due for review on a spaced schedule.
- **Song details and cover art**: each song can carry a key, genre, album, year, personal notes (Markdown) and cover art (PNG, JPEG or WebP). The key is detected from a tab's notes (Krumhansl-Schmuckler) or a chord sheet's `{key}` (estimated from its chords when it has none) unless you set one; the library cards show it and the library filters by key and genre. `FRETBOOK_METADATA_LOOKUP=true` adds an opt-in lookup of album, year and cover on MusicBrainz and the Cover Art Archive. See the [song details guide](docs/guides/song-details.md).
- **Practice log**: the time you spend playing a tab is logged automatically, per song, track and loop, with the speed (time-weighted) and the mode (free play, wait mode, or scored play-along with its score). In wait mode, time stuck on one note with no input stops counting after about two minutes, until you move on. A chord sheet has no playback, so it has an opt-in **I'm practising this** switch under the sheet: while it is on and the page is visible, the time is logged as free play, and it pauses after five minutes without a tap, key or scroll. Chord sheets show their practice history too. A pause shorter than a minute stays in the same session, and stretches under five seconds are not logged. The _Practice_ page shows a progress ring for the day's minutes against your daily goal (default 15, 0 turns it off), the current and longest streak, songs practised, a calendar heatmap of minutes per day, a weekly summary, recently practised songs, best scores, and songs you haven't played in two weeks. Each tab's page has its own practice history. Days follow your browser's local midnight. The log is part of the library backup (existing sessions are never duplicated on a second restore).
- **Setlists**: named, ordered lists of songs for a rehearsal or a gig. Reorder by dragging or with the keyboard, add a note per song (key, capo, "skip solo") and a transpose per chord sheet, then _Play through_ to step from song to song (Alt with ← or →). _Export PDF_ makes one file with a contents page followed by every song. A song can be in many setlists, and setlists are part of the library backup.
- **Languages**: English and Brazilian Portuguese.

Fretbook grew out of [Mr-P4p3r/bass-tab-sync](https://github.com/Mr-P4p3r/bass-tab-sync) and still imports its `songs/` folders.

## Run it

### Docker

```sh
docker compose up --build
```

Open `http://localhost:8137`. The database and audio live in the `fretbook-data` volume. A `./songs` folder is mounted read-only for bass-tab-sync imports.

Prebuilt images for amd64 and arm64 are published to GHCR. Each release (`vX.Y.Z`, listed in [CHANGELOG.md](CHANGELOG.md) and on the [releases page](https://github.com/liftedkilt/fretbook/releases)) gets the tags `X.Y.Z` and `X.Y`; every push to `main` gets `latest`, `main` and `sha-<commit>`.

```sh
docker pull ghcr.io/liftedkilt/fretbook:latest   # newest main
docker pull ghcr.io/liftedkilt/fretbook:0.1.3    # a release; pin this one
```

**Upgrading.** Back up the `/data` volume, read the [changelog](CHANGELOG.md), then `docker compose pull && docker compose up -d`. Migrations run on start and are not reversible; see [Upgrading](https://liftedkilt.github.io/fretbook/self-hosting/upgrading/).

### Locally

Python 3.12, Node 22, and ffmpeg (only for downloading YouTube audio).

```sh
./run.sh            # creates .venv, builds the web app, starts on http://127.0.0.1:8137
```

For development, see [CONTRIBUTING.md](CONTRIBUTING.md).

Without sign-in, anyone who can reach the port can use the library, so keep a no-login server on a trusted network or behind an authenticating proxy. To report a vulnerability, see [SECURITY.md](SECURITY.md).

To build the docs locally: `pip install -r requirements-docs.txt && mkdocs serve`. `cd web && npm run docs:screenshots` regenerates the screenshots.
